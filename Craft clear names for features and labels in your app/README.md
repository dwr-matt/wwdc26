# Craft clear names for features and labels in your app

# WWDC 2026 Session Summary: Craft Clear Names for Features and Labels

## Overview
This session, led by a UX writer from Apple’s Human Interface Design team, focuses on the critical—and often overlooked—discipline of naming within software applications. The session argues that naming is as fundamental to user experience as visual design and interaction patterns. By adopting a systematic approach to choosing labels and feature names, developers can build user trust, set accurate expectations, and create a cohesive "language" for their apps that feels intuitive and professional.

---

## Key Concepts
The speaker introduces three primary criteria for evaluating the quality of a name. While not a rigid rulebook, these provide a framework for testing potential labels:

1.  **Belongs:** The name fits seamlessly into the app's ecosystem, matching the tone and logic of other existing labels.
2.  **Expectations:** The name provides clarity, allowing users to accurately predict what will happen when they interact with a feature. This builds trust by preventing confusion.
3.  **Works Everywhere:** The name remains effective across different languages, markets, and varying technical contexts.

### The "Audience-First" Perspective
A common pitfall for developers is naming features based on internal engineering logic or technology-stack terminology. The session emphasizes shifting the focus from **"what it does"** (the technology) to **"what it does for the user"** (the benefit).

---

## Techniques and Methodologies

### The "Think, Feel, Do" Exercise
To arrive at the right name, the speaker recommends a brainstorming exercise focused on the user’s journey:
*   **Think:** What should the user understand about the feature? (e.g., "This is helpful," "This is secure").
*   **Feel:** What emotional response is intended? (e.g., confident, secure, excited).
*   **Do:** What is the primary action the user should take? (e.g., find, share, enable).

### The "Gut Check" Evaluation
*   **Verbalization Test:** Say the name out loud in a natural sentence (e.g., "Hey, check out [Feature Name]"). If it sounds like jargon or a spreadsheet header, it likely doesn't "belong."
*   **The "Judgment" Test:** Evaluate if a label could be perceived as negative or judgmental if the user’s status changes (e.g., avoiding terms that imply a lack of progress when a user has a low balance).
*   **Grouping/Theming:** After generating a high volume of sticky-note ideas, group them by theme (e.g., Ease, Security, Emotion) to see which concepts align best with the app's brand.

---

## Practical Takeaways for Developers

*   **Standardization over Cleverness:** In high-stakes areas like finance or system settings, standard industry terminology (e.g., "Balance") is often superior to creative, branded language, as it minimizes cognitive load and maximizes trust.
*   **Verbs for Control:** If a feature is something a user *does* (e.g., modifying audio), use a verb-based name to put the user in control, rather than a passive noun.
*   **Balance Brand and Clarity:** You do not have to abandon brand voice entirely. If a "fun" name (like "Heavyweight/Lightweight" for gym tiers) is chosen, acknowledge that it requires more effort to explain. Lean into clarity for utility, and emotion for features that connect with the user’s life (e.g., Apple’s "Memories" feature).
*   **Compound Naming:** When a clear, single word doesn't exist, you can create one from two known parts that explain themselves (e.g., "Auto-mix").
*   **Names Accumulate:** View naming as a long-term architectural decision. Every good name you choose makes the next one easier, eventually creating a consistent, predictable, and professional language for your entire platform.
